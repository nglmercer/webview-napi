# Contributing

Thanks for contributing to `webview-napi`! The project is MIT-licensed and built with
Rust (NAPI-RS) + `tao` + `wry`, with a TypeScript API and a Bun/Node toolchain.

## Setting up

```bash
bun install          # TS toolchain
bash ./scripts/install-linux-deps.sh   # Linux system deps (WebKitGTK etc.)
```

## Common commands

| Action | Command |
| --- | --- |
| Build (debug) | `bun run build:debug` |
| Build (release) | `bun run build` |
| Build the WebviewHost | `bun run build:host` |
| Check Rust | `bun run check` · `bun run clippy` |
| Lint | `bun run lint` · `bun run lint:fix` |
| Format | `bun run format` (prettier + `cargo fmt`) |
| Test | `bun test __test__/` · `bun run test` |
| Docs (Rust) | `bun run docs` |

> `bun run build:debug` is also the fastest way to regenerate `index.d.ts` /
> `index.js` after changing Rust. Examples import these local files, so rebuild before
> running an example.

## The two API layers

- Rust sources live in [`src/`](../src) (`tao` windows, `wry` webviews, `high_level.rs`).
- `index.js` / `index.d.ts` are generated by NAPI-RS from `src/lib.rs`. Don't edit them by
  hand — edit the Rust and rebuild.
- `runtime.js` / `runtime.cjs` are the promise-based runtime facade over the embedded and
  process backends (see [`docs/webview-runtime.md`](webview-runtime.md)).

## Submitting changes

1. Fork the repository.
2. Create a feature branch (`git checkout -b feature/amazing-feature`).
3. Make your change — keep examples focused and the docs updated.
4. Run `bun run format`, `bun run lint`, and the test suite.
5. Open a pull request.

Bug reports and feature requests are welcome in the issues tracker. For questions about
the upstream libraries: [tao](https://github.com/tauri-apps/tao),
[wry](https://github.com/tauri-apps/wry), [napi-rs](https://github.com/napi-rs/napi-rs).
